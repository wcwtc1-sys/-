B. Player 当前控制流程

Player 身上叠了 8 个 MonoBehaviour，控制流分三个平行层。

B.1 移动层 —— PlayerController.cs（495 行）

  • CharacterController 驱动，每帧只调用一次 Move()（水平 + 垂直 + 外力合并，ApplyGravityAndMove L445-L461）—— 为修 "移动中不能跳" 专门设计。
  • 土狼时间 coyoteTime（L432-L441）；跳跃不耗体力。
  • 翻滚：rollDistance / rollDuration / 无敌帧窗口 / rollStaminaCost。
  • 体力：max 100、+25/s、延迟 0.6s；只被翻滚消耗。
  • 攻击前冲 ApplyLunge：前快后慢曲线（Lerp(1.25,0.35)/0.8 保证位移 ≈ distance），可被翻滚取消。
  • 三种"停手"语义：
  • SetMovementBlocked —— 攻击中锁移动，翻滚仍可用
  • SetMoveSpeedMultiplier —— 格挡减速
  • SetControlEnabled —— 阵亡，全部失效
  • PushOut：外部推挤，与君主"体型分离"配合（避免一帧两次 Move 导致 isGrounded 闪烁）。
  • 锁定转向：SetLockOnTarget 后角色恒面向君主，WASD 变绕行走位。

    D.2 驱动方式（关键设计）

    PlayerModelAnimator.cs（794 行）不使用 Animator 状态机。它把 controller 当成按状态名寻址的片段播放器：

    animator.CrossFadeInFixedTime(stateName, 0.06f, 0, 0f);  // L757
animator.speed = speed;                                   // L766

    speed 由 片段时长 ÷ 该状态应有的时长 反算（L657-L675），于是 1.07s 的挥砍被压进 0.4s 的轻击窗口。攻击时更进一步分两段给倍率：

    • 前摇段：让片段 [0, contactFraction] 正好演完前摇；
    • 收招段：只演 recoveryPortion（默认 0.45），跳过片段尾部的静态收势。

    效果：判定帧被钉死在接触帧上，同时保留片段内部的"前摇慢、出刀快"节奏（匀速压缩会把它压平）。

    这与 PROJECT_STATE.md §6 的硬约束一致：判定走计时器，不走动画事件。

    G. 存在的问题

    G1 · 真实代码缺陷（有明确证据）

  • AttackClipProfile 键名对不上，重击的调参是死的。

    • PlayerModelAnimator.cs:637 重击用 state = "AttackB1"，ContactFraction("AttackB1") 查不到 profile → 回落默认 0.40；但场景 attackProfiles 里配的是 AttackHeavy: contactFraction 0.45。0.45 这个值从未生效。

  • 重击片段与三段普攻片段来源不同，双手剑动作不统一。

    • 三段普攻 = DoubleL 单手 1Hand_Up_Attack_A_1/2/3；重击（B1）= DoubleL 单手 1Hand_Up_Attack_B_1；只有 AttackHeavy（未使用）才是 Blink 的 MeleeAttack_TwoHanded。玩家拿着大剑，却在播单手剑连段。

  • 两个玩家外观系统并存，靠"每帧关掉另一个"维系。

    • PlayerVisuals 与 PlayerModelAnimator 同挂 Player；后者在 LateUpdate 里 EnsureProceduralHidden() 每帧查询并 SetActive(false)。注释也承认"PlayerVisuals 在它自己的 Awake 里才构建 Visual 节点，执行顺序不定"。脆弱的顺序耦合。

  • Boss 完全没有动画。 Boss_Monarch 无 Animator、无 SkinnedMeshRenderer。"亡灵君主"的正式美术接入是零起步工程。
  • Animator 靠字符串状态名驱动，无编译期保护。 拼错状态名 → CrossFadeInFixedTime 静默失败，角色定格。m_AnimatorParameters: [] 意味着无法用参数/触发器，只能拼字符串。
  • 判定层没有 Layer 配置。 所有 OverlapSphere 的 LayerMask 都是 Everything，靠 IsChildOf 和 CompareTag("Player") 排除。加入任何新单位（第二个敌人、可破坏物、召唤物）时必须显式排除，否则立刻出现自伤/误伤。这是"还没规模化就埋下的坑"。
  • 场景与 C# 默认值大面积不一致，且没有数据资产层。

    • 例：PlayerCombat.lightWindup C# 默认 0.12 vs 场景 0.4；PlayerController.rollDuration 默认 0.33 vs 场景 0.68。GDD §10 声称"资源参数走 ScriptableObject"，但 Assets/_Game 下只有 2 个 .asset（PanelSettings 与大剑 Mesh），没有任何技能/阶段数据资产 —— 改数值必须打开场景。

  • 硬编码的名字/标签查找。
    • BossController.Awake L370：GameObject.FindGameObjectWithTag("Player")
    • SummonedWraith.Awake L59：同上
    • LockOnController L57/L62：FindObjectOfType<BossController>() / FindObjectOfType<HudController>()
    • PlayerHealth L156：GameObject.Find("PlayerSpawn")
    • BossController L384：GameObject.Find("ArenaCenter")

    改名/改层级就会静默失效。

  • 静态列表的初始化顺序问题仍然存在。

    • Pillar.All 由 OnEnable 填充，与 Awake 顺序不定（PROJECT_STATE §8.1 记录过实测错误"剩余石柱 3/1"，HudController 里已改用 FindObjectsOfType<Pillar>() 绕过）。根因没修，只是绕开了。

  • TryPlayHit(float dt) 的参数 dt 从未使用，且用"TimeSinceLastDamage 变小"来推断"又挨打了"（L596-L601）。顿帧会改 timeScale，多来源同帧伤害也会漏判。
  • TryPlayHeal 硬编码了 2.0 秒（ClipLength("AttackUltimate") / 2.0f，L557），复刻了 PlayerHealth.healChannelTime。改治疗吟唱时长会让动画倍率错位。
  • Player 根节点残留白盒的 MeshFilter + MeshRenderer（classID 33/23），清理遗漏。
  • SummonedWraith / BossVisuals 无条件用 _BaseColor/_Color 染所有 MeshRenderer —— 接入带贴图的正式模型后会被染成单色。亡魂侧已加 applyTint 开关，BossVisuals 侧没有。
  • 没有 .asmdef，没有 .git。 35 个脚本全在 Assembly-CSharp，任何改动全量重编；没有版本控制，改动不可回退、不可对比。
